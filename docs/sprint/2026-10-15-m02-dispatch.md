## Debug receipts (honest, kept for who comes next)

The e2e did NOT come up first try. Fixes were earned in this order:
1. `PYTHON_COMMAND` unbound under `set -u` (edksetup.sh reads it unguarded).
2. `EDK_TOOLS_PATH` unbound — relax `-u` for the sourcing only.
3. `CONF_PATH` dir must exist before BaseTools/BuildEnv writes into it.
4. `GCC5` gone in this generation → plain `GCC` toolchain tag; and `-b` is
   the build target, not the toolchain (RELEASE).
5. Package root: PACKAGES_PATH must contain BOTH the EDK2 tree (MdePkg) and
   our `efi/edk2/`; `[Components]` paths are relative to packages root.
6. Library class renames: RegisterFilterLib→RegisterFilterLibNull instance,
   StackCheckLib→StackCheckLibNull, DebugPrintErrorLevelLib class name,
   UefiDevicePathLib.h → DevicePathLib.h.
7. `-Wextra` + generated AutoGen.c unused params → `-Wno-unused-parameter`.
8. Local variable named `FileDevicePath` shadowed the library function.
9. ESP FAT32 at small sizes won't boot under OVMF (cluster minimum) → FAT16.
10. First e2e "PASS" run had a copy-before-flush race on the honest-return
    line → settle-sleep before kill.
