# M0.6 — `cellbootctl`: install / status / uninstall

Status: ⬜ planned

## Goal

Turn everything from M0.1–M0.5 into a **usable product**: a `bootctl`-style
CLI that installs CellBoot onto a user's system, reports its state in
receipts (not vibes), and uninstalls cleanly without leaving a zombie EFI
chain behind.

Shape precedent: `acreetbootctl/acreetbootctl.py` (install / uninstall /
status / set-bootnext / verify). CellBoot is its own program though —
deliberately separate repo, separate tool, chain glue stays coordinated in
acreetboot #3.

## Deliverables

1. `cellbootctl/` (language: python, stdlib-only, matching the repo's
   stdlib discipline; or C-binary if acreetboot's acreetbootctl evolves
   there — decide at build time in coordination with acreetboot).

   Subcommands:
   - `install` — carries out:
     - detects ESP (`FindPartitionbyGPTPartUUID`, / `bootctl`-sane
       detection); refuses if sd-bootdrivers aren't present (parity with
       acreetboot's install honesty),
     - copies `CellBootLauncher.efi` → `\EFI\cellboot\CellBootLauncher.efi`
       (src of truth: build receipt sha256 — footsteps recorded),
     - stages the microkernel+initramfs payload on the ACREETBOOT-ZSWAP
       or M.2 XBOOTLDR partition (decide + document),
     - writes the sd-boot/loader entry chain (`10-cellboot-dboot.conf`
       or `cellboot` package entries per acreetboot's lane),
     - installs `/EFI/acreetboot/`-equivalent `\EFI\cellboot\` firmware
       chain markers,
     - NVRAM: sets `BootNext`-able `BootOrder` for the cellboot entry without
       demolishing user's existing choices.
   - `status` — receipts on current state:
     - marker present / sha256 match vs installed copy,
     - NVRAM `BootOrder`/`BootNext` glance + guard liveness,
     - last harness run receipt pointer (if run locally).
   - `uninstall` — removes `\EFI\cellboot\`, sd-boot entries, restores
     `BootOrder`, and *not* the guard (guard-remove must be explicit sub
     command `uninstall --keep-nvram-guard` for recovery tools — be
     conservative by default).
2. `man/cellbootctl(1)` page.
3. `test/test_cellbootctl.py` + e2e: inside QEMU/OVMF or a stubbed
   environment; asserts install produces a bootable desc-and-marker boot;
   uninstall restores NVRAM.

## Acceptance criteria

- [ ] install → status → uninstall round-trip green in the committed e2e;
      NVRAM verified clean after uninstall (no orphan `BootOrder` entries).
- [ ] All receipts sha256-verified at `status` time; a mismatched install
      is reported, never hidden.
- [ ] man page ships with the sub-commands documented.

## Dependencies

M0.5 (guard must exist — install wires it; uninstall must consider it).

## Out of scope

Secure Boot / UKI path, kexec-only chain alternatives (acreetboot 0.6.5
lane). Mirror them here later, documented as tracked-future.
