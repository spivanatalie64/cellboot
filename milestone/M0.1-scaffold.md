# M0.1 — Repo scaffold + EDK2 bootstrap

Status: 🟢 **partially done** — README, LICENSE, .gitignore, general_summary.md
landed (commit `9cd4644`); the working scaffold and EDK2 bootstrap remain.

## Goal

Stand up the full proposed directory tree and the build-time discipline
before any EFI code exists: when M0.2 starts, it compiles inside
infrastructure that is already pinned, checked, and tested — not ad hoc.

## Deliverables

1. Directory tree per issue #1:
   ```
   build.sh
   efi/edk2/CellBootPkg/          # EDK II package (DSC/INF)
   ├── CellLauncher/              # main EFI app
   └── CellBootStub/              # OVMF payload stub for e2e proof
   initramfs/                     # KVM-host minimal initramfs source (busybox-ish)
   c/                             # userspace C helpers (device-path resolver, NVRAM guards)
   test/                          # run_all.sh + OVMF e2e harness
   docs/plan/00-PLAN.md           # lifecycle, milestones, hardening model
   docs/sprint/                   # per-day logs
   man/                           # cellboot(1)
   milestone/                     # this milestone set (00-INDEX + M0.x)
   ```
2. `tools/edk2-bootstrap.sh` — clone a **sha256-pinned `edk2-stable`** tag
   (+ required submodules, e.g. brotli/mipisyst as taken working from
   acreetboot's `tools/edk2-bootstrap.sh`), never commit the EDK2 tree
   (goes under `build/`, already in .gitignore).
3. `build.sh` — syntax-check + build + test entrypoint, mirroring
   acreetboot's shape. Must fail loudly on missing toolchain (gcc, make,
   edk2 `build`), never fake success.
4. `docs/plan/00-PLAN.md` — the rationale doc: why `\EFI\cellboot\`, why
   KVM-guest Windows, hardening model, licensing posture (already captured
   in general_summary.md; this is its canonical long-form home).
5. Empty `CellBootPkg` skeleton: DSC/INF files that resolve (package builds
   as a no-op stub), `CellBootStub` placeholder.
6. `test/run_all.sh` — runs the harness even when it is just "nothing to
   run yet", exits 0 honestly, so CI has something from day one.

## Acceptance criteria

- [ ] `./build.sh` completes on a stock AcreetionOS/Arch dev machine; the
      EDK2 tree it fetches matches recorded sha256s (receipt in build/).
- [ ] `test/run_all.sh` green; `milestone/` committed; issue #1 scaffold
      directions carried into reality (or deliberately deviated, with the
      deviation documented — e.g. this `milestone/` dir instead of planting
      the plan only under `docs/plan/`).

## Dependencies

None — first milestone.

## Out of scope

Any real payload dispatch, guest VM, or Windows logic (M0.2+).
