# M0.2 — `CellBootLauncher.efi` boots a hardcoded PE32+ payload

Status: ⬜ planned

## Goal

Prove the core mechanism of the whole project: an EDK II UEFI application
at `\EFI\cellboot\` can load and start an arbitrary PE32+ payload via
`LoadImage` + `StartImage`. Everything downstream (M0.3+) is this same hop
with a different payload; prove the hop first, in firmware, hands-off.

Direct precedent: acreetboot milestone 0.2 — `AcreetMainMenu.efi` boots a
single hardcoded PE32+ payload, proven end-to-end in QEMU/OVMF with the
`ACREET-PAYLOAD-OK` serial marker. CellBoot reproduces that model under the
CellBoot/tree identity with marker **`CELL-PAYLOAD-OK`**.

## Deliverables

1. `efi/edk2/CellBootPkg` (real DSC/INF package; built by the sha256-pinned
   EDK2 from M0.1):
   - `CellLauncher/` — `CellBootLauncher.c`: hardcoded device path to the
     payload, `EFI_BOOT_SERVICES.LoadImage` + `StartImage`, honest error
     paths (`EFI_NOT_FOUND` / `EFI_LOAD_ERROR` ⇒ explicit serial print +
     no fake continue).
   - `CellBootStub/` — `Cellbootstub.c`: two-line PE32+ stub that writes
     the serial marker and exits, purely an e2e proof stand-in (same role
     as `AcreetBootStub.c`).
2. `test/test_ovmf_boot.sh` — QEMU/OVMF harness:
   - builds OVMF VARS/VM pair (upstream ovmf package, or cleaned vars as in
     acreetboot's harness),
   - stages an ESP image containing `\EFI\cellboot\CellBootLauncher.efi`
     and the stub payload,
   - boots headless (`console=ttyS0`-equivalent firmware output), captures
     serial, asserts `CELL-PAYLOAD-OK`, bounded runtime, `-no-reboot`.
3. The stub carries `EFI_NT_FUNCTIONS`-compatible SB signing inside the test
   (signed or with SB check mode disabled explicitly in-OVMF-config,
   documented — do not leave an undocumented insecure boot).

## Acceptance criteria

- [ ] `test/test_ovmf_boot.sh` green: serial shows `CELL-PAYLOAD-OK`.
- [ ] `test/run_all.sh` includes it.
- [ ] No `EFI\Microsoft\` path touched anywhere (grep-guard the test image).

## Dependencies

M0.1 (EDK2 pinned, build.sh works).

## Out of scope

Linux guest, KVM, any dynamic device-path resolution — this milestone is a
hardcoded hop on purpose.
